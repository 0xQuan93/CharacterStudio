# Humanoid source assets and the limits of avatar randomization

Verified 2026-09-17. This audit separates a ready-to-load historical VRM from a source pack for a future parametric human generator. Downloading a model does not restore the creator's original modeling controls.

### What the female VRM really adds

It adds a different complete body/hair silhouette and a useful hair-texture case: two hair materials across 108 hair primitives. The hair is already skinned and spring-driven. The hair is not a ready-fitted interchangeable attachment for the male base: skeleton mapping, fit and spring/collider references must be reconciled before that can become a supported operation.

There are 41 facial morph targets, not 41 anatomical sliders. Their names live in `meshes[0].primitives[0].extras.targetNames`. They describe expressions, eye closure, mouth phonemes, fangs and an eye overlay; 15 are bound by the VRM expression groups. Body and hair contain no authored morph targets. Unbound facial expression parts should not automatically become identity randomization controls. The receipt records counts and material names so UI adapters can be deliberate.

## MPFB is the strongest reusable human foundation

The project expressly permits using its base mesh, targets and system assets to create another character generator. Its asset license covers mesh/proxy data, targets, textures, clothes, rigs and expressions as CC0. MPFB application code is GPLv3; no application code was copied into Character Studio. [Generator reuse FAQ](https://static.makehumancommunity.org/mpfb/faq/build_other_chargen.html), [pinned split-license definition](https://github.com/makehumancommunity/mpfb2/blob/817587ceb2ea03ea17a5b47e04396cbb4ddfa2d5/LICENSE.md).

The staged OBJ has 19,158 vertices and 18,486 polygons, including modeling helper groups. The accompanying game-engine rig has 53 named bone definitions. The target subset contains head (27), nose (42), chin (15), cheek (16), brows (6) and mouth (44) targets. Each is compressed vertex-index displacement data. The receipt records affected-vertex counts and maximum indices; all staged targets were decompressed and parsed. The full inspected upstream tree has 1,258 `.target.gz` files; that number is inventory, not a claim that every file forms an independent user slider.

MPFB documents targets as vertex displacements and macro controls as combinations of targets. Consequently, direct target application requires the matching vertex order and topology. A MakeHuman nose target cannot be applied by index to a VRoid face. A transfer system would need a fitted correspondence and deliberate handling of eyelids, mouth cavities, asymmetry and expression shapes. [Target concepts](https://static.makehumancommunity.org/mpfb/docs/assets/concept_targets.html).

A practical future ingestion pipeline is: retain the MPFB source topology and target identities; remove helpers only with an explicit original-to-export vertex map; select a bounded morphology subset; refit rig joints and garments after shape changes; export a GLB/VRM with compatible identity morphs; validate blink/phonemes and joint motion; add asset-specific randomization ranges. The staged source data makes this possible without licensing a proprietary base. It does not implement this pipeline by itself.

## Consequences for sculpting Quan

Use the existing approved front and profile references to author bounded geometry edits on one chosen topology. Preserve a neutral identity layer separate from animation expressions. Keep randomization limited to verified identity controls, fitted asset choices and color palettes. Randomly mixing every exported expression target creates expressions or broken anatomy, not a reliable character generator.

Hair highlights can be painted on the existing UV texture and survive portable image embedding. Shared hair UV islands intentionally repeat the painted pattern. Unique strand highlights require distinct UVs or materials. Moving hair silhouettes needs geometric hair controls or authored hair meshes; painting alone cannot create the swept fringe. These are independent work streams, and neither texture color nor generic whole-object scaling should be presented as a substitute for sculpting.

The implemented local texture painter uses one draft highlight layer over the source, brush/erase, size, opacity, ten draft undo states, and alpha-preserving composition. Applying flattens the draft to a PNG texture; project Undo remains the durable rollback. It does not claim persistent multi-layer files, hair-curve generation, 3D surface painting or UV seam repair. That bounded surface workflow is useful immediately and leaves the source geometry/VRM rig intact.

Standalone browser verification passed at 1100×800, 390×844 and 800×400: real pointer strokes changed texture pixels; Undo restored the exact original canvas; PNG output retained every source alpha byte (including semi-transparent pixels); dialogs and Apply actions stayed within the viewport; zero page errors. Evidence: `avatar-tools/check-texture-painter.cjs` and `avatar-tools/logs/texture-painter-*.png`. This test covers the component; the host app still needs its own export/reimport acceptance.

The seeded generator (`src/workbench/generator.js`) now chooses semantic skin/hair/eye/brow swatches and only the three exact authored identity target names (jaw width, chin length, nose width), bounded to ±0.55 or a narrower authored range. The appearance adapter excludes expression-bound targets. It returns a shallow project patch, preserving unrelated colors/morphs and all texture/sculpt/source state. Channel-specific seeds keep results stable when descriptor order changes. The female sample consequently receives palette variation without pretending its expression shapes are anatomy. Automated tests exercise these constraints and seed reproducibility.

Production painter acceptance after shader preservation fixes: `avatar-tools/check-workbench-paint-export.cjs` passed tinted black hair → mint highlight stroke → PNG embedding → VRM export/reimport and portable project reopening. Shared MToon shade/base textures both reference the new embedded image. Export/reimport mean absolute pixel error was at most 0.000011 per RGB channel (0–255 range); no pixels differed by more than 5. Blank Apply closes without modifying an empty/fully undone/cleared draft, and measured approximately 0.0002 mean error from renderer motion. Project reopening measured below 0.00034. Actual painting visibly changed 12,125 pixels. Zero browser page errors. Reports and comparison PNGs are in `avatar-tools/logs/paint-hair-*`. This verifies the staged material workflow, not arbitrary imported custom shaders.

Female model production acceptance also passed (`avatar-tools/check-workbench-female.cjs`): both hair materials expose usable painter controls; a seeded variation changes only the six bound material colors and leaves morphs empty, with source, textures, sculpt state, visibility and scale intact. Saved portable source hash exactly matches the runtime derivative receipt. The generated VRM has zero validator errors; the pre-existing legacy warnings remain. Screenshot `avatar-tools/logs/female-variation-studio.png` was visually inspected. The source hairstyle includes twin tails and cat-ear shapes, which are part of this complete historical sample rather than a fitted Quan hairstyle.
